# M1 낙상감지 베이스라인 결과 (2026-09-16)

자체 수집 3노드 CSI로 학습한 첫 베이스 모델의 측정 기록이다.
**결론부터: 일상·빈방에서는 거의 오탐이 없지만, 하드 네거티브(앉기·눕기)에서는
거의 전부를 낙상으로 판정한다. 8/2 구모델보다 이 항목은 더 나빠졌다.**

---

## 1. 오늘 수집 요약

| 항목 | 값 |
|---|---|
| 낙상 이벤트 | **48건** (FALL 세션 9개) |
| 하드 네거티브 | **45건** — 의자에 앉기 / 바닥에 앉기 / 눕기 |
| 일상 활동 | 4.4분 |
| 빈 방 | 8.2분 |
| 파일 | 34개 (`data/raw_main/`) |
| 센서 | 3노드 · 100 Hz |
| 노드 커버리지 | 평균 **88.9%** (평가 13파일 실측, epoch 격자 정렬 시 손실) |

낙상 48건은 `data/labels_main.csv`의 `fall_ts_ms` 개수를 세어 확인했다.

## 2. 학습 설정과 결과

```
입력      (B, 3, 64, 100)   노드 3 × 부반송파 64 × 100프레임 (1초 @ 100Hz)
모델      CNN-GRU · conv [16,32,64] · GRU hidden 64 · dropout 0.5
출력      fall_logit (B,1)  pre-sigmoid
창        stride 50 · 낙상 근처 fall_stride 20 · 양성 판정 ±1000ms, pos_frac 0.5
학습      lr 3.0e-4 · batch 64 · weighted_sampler · primary_metric pr_auc
라벨      data/labels_split.csv  (하드 네거티브 7파일은 여기 없음 = 미학습)
```

| | 값 |
|---|---|
| train | 2192창 (양성 346) |
| val | 924창 (양성 225, 양성비 0.244) |
| **best epoch** | **8** |
| pr_auc | **0.472** |
| fall_recall | 0.702 |
| precision | 0.521 |
| f1 | 0.598 |

랜덤 대비 **1.93배** (pr_auc 0.472 / 양성비 0.244).
7월 공개데이터 CSI-Bench는 0.685 / 0.521 = 1.31배였다.
학습 곡선은 8에폭에 걸쳐 오르다 내려갔다 — 정상적인 과적합 전환이다.

## 3. 이번 측정 (하드 네거티브 오탐률)

`scripts/eval_hardneg.py` · 체크포인트 `runs/best.pt` (ep8) · **strict=True 로드** ·
출력 logit에 **sigmoid 1회 적용** · 창 단위 결과는 `out/eval_hardneg.csv`.

평가 대상은 **모델이 학습에서 보지 않은 것만** 골랐다 (`data/labels_eval.csv`, 13파일):
하드 네거티브 7파일(학습에서 완전 제외) + val이었던 일상 3파일 + val이었던 낙상 3파일.
train이었던 파일은 한 개도 넣지 않았다.

### 측정이 학습과 같은 파이프라인인지 확인

평가는 `m1_fall.dataset.build_split`을 그대로 썼다. 결과가 학습과 맞물린다:

| 확인 | 값 |
|---|---|
| 평가 전체 창 | 1407 |
| − 하드 네거티브 창 | 483 |
| = 나머지 | **924** = 학습 val 창 수와 일치 |
| 양성 창 | **225** = 학습 val 양성 수와 일치 |
| 재현율 @0.5 | **70.2%** = 학습 `fall_recall` 0.702와 일치 |

숫자가 재현됐으니 전처리·창 나누기·라벨 부여가 학습과 동일하다고 볼 수 있다.

### 표 1 — 오탐률 (라벨 0 = 비낙상 창을 낙상이라고 한 비율, **낮을수록 좋다**)

| 그룹 | 창 수 | ≥0.5 | ≥0.7 | 중앙값 | p90 |
|---|---:|---:|---:|---:|---:|
| **hardneg_chair** (의자에 앉기) | 200 | **98.5%** | **96.0%** | 0.968 | 0.983 |
| **hardneg_floor** (바닥에 앉기) | 116 | **100.0%** | **99.1%** | 0.971 | 0.985 |
| **hardneg_liedown** (눕기) | 167 | 35.9% | 26.9% | 0.237 | 0.967 |
| normal_active (일상 활동) | 119 | 0.0% | **0.0%** | 0.068 | 0.170 |
| normal_empty (빈 방) | 238 | 4.6% | **1.7%** | 0.123 | 0.365 |
| fall 세션의 비낙상 구간 | 224 | 50.4% | 46.4% | 0.609 | 0.976 |
| fall_longlie 세션의 비낙상 구간 | 118 | 17.8% | 15.3% | 0.141 | 0.807 |

- **하드 네거티브 7파일 통합: 483창 · ≥0.7 발동률 72.9% · 중앙값 0.950**
- 일상+빈방 3파일 통합: 357창 · ≥0.7 발동률 **1.1%** · 중앙값 0.100

> `fall`/`fall_longlie` 세션의 "비낙상 구간"이 46.4% / 15.3%로 높은 건 두 가지가 섞여 있다.
> ① 낙상 연습 세션이라 비낙상 구간도 낙상 직전·직후의 큰 움직임이다(라벨 경계 효과).
> ② 모델이 실제로 움직임에 반응한다. 둘을 이 측정만으로는 분리할 수 없다.

### 표 2 — 재현율 (라벨 1 = 낙상 창을 맞힌 비율, **높을수록 좋다**)

| 그룹 | 창 수 | ≥0.5 | ≥0.7 | 중앙값 | p90 |
|---|---:|---:|---:|---:|---:|
| fall | 177 | 80.8% | 72.9% | 0.902 | 0.980 |
| fall_longlie | 48 | 31.2% | 22.9% | 0.198 | 0.909 |
| **전체** | **225** | **70.2%** | **62.2%** | — | — |

**파일 간 편차가 매우 크다** (이게 지표 신뢰도의 핵심 한계다):

| 파일 | 양성 창 | 재현율 @0.7 | 중앙값 |
|---|---:|---:|---:|
| `1327_fall` | 129 | **86.0%** | 0.920 |
| `1340_fall` | 48 | **37.5%** | 0.427 |
| `1345_fall_longlie` | 48 | **22.9%** | 0.198 |

전체 재현율 70.2%는 사실상 `1327_fall` 한 파일이 끌어올린 값이다
(양성 225창 중 129창 = 57%가 그 파일에서 나온다).
같은 행동인 `hardneg_liedown`도 파일마다 5.6% vs 51.3%로 갈린다.

## 4. 8/2 실측과의 비교

2026-08-02 rp5 실측은 **단일노드 구모델**을 rp5에서 0.6초 간격 실시간 추론한 것이고,
이번 측정은 **3노드 신모델**을 수집 파일에 창 단위로 돌린 것이다.
모델·노드 수·측정 방식·환경이 모두 달라 **직접 비교가 아니다.** 경향만 본다.

| 조건 | 8/2 구모델 ≥0.7 | 오늘 신모델 ≥0.7 | 방향 |
|---|---:|---:|---|
| 빈 방 | 0.15% | 1.7% (normal_empty) | 둘 다 무시 가능 |
| 가만히 앉기 / 일상 | 0% | 0.0% (normal_active) | 동일하게 좋음 |
| 천천히 걷기 | 32% | (해당 그룹 없음) | 측정 안 함 |
| **빠르게 앉기** | **54%** | **96.0%** (의자) / **99.1%** (바닥) | **더 나빠졌다** |

**핵심 질문 "8/2보다 나아졌는가"에 대한 답: 앉기 오탐은 나아지지 않았고 더 나빠졌다.**

8/2 때 진단한 원인은 "모델이 낙상이 아니라 모션 강도를 본다"였다. 그 진단은
오늘도 그대로 유효하다. 오늘 모델은 하드 네거티브를 **한 번도 보지 않고** 학습했으므로
"빠른 자세 변화 = 낙상"을 그대로 학습했고, 그 결과가 96~99%다.

반대로 좋아진 것도 분명하다: 일상 활동 0.0%, 빈 방 1.7%로 **정적인 상황의 오탐은 거의 없다.**
문제는 낙상과 비슷한 움직임을 가려내지 못하는 것 하나로 좁혀졌다.

## 5. 한계 (숨기지 않고 적는다)

1. **1인 · 1실 · 1일 데이터다.** 피험자·환경 일반화는 전혀 검증되지 않았다.
   다른 사람, 다른 방에서 이 숫자가 유지된다는 근거가 없다.
2. **하드 네거티브는 학습에서 제외했고, 해결은 10월로 미뤘다.** 이번 오탐률은
   "아직 안 가르친 것을 못 맞힌다"는 당연한 결과이지, 모델 구조의 한계 측정이 아니다.
3. **val 양성이 낙상 19건에서만 나와 지표 분산이 크다.** 위 파일별 표에서 보듯
   같은 지표가 파일에 따라 22.9%~86.0%로 흔들린다. 전체 재현율 70.2%를
   "이 모델의 성능"으로 읽으면 안 된다.
4. **노드 커버리지 평균 88.9%다.** epoch 격자 정렬에서 약 11%의 슬롯이 0으로
   패딩된다. 이 손실이 성능에 얼마나 영향을 주는지는 측정하지 않았다.
5. **8/2 비교는 조건이 다르다.** 모델(단일노드 vs 3노드), 측정 방식(rp5 실시간 vs
   파일 창 단위), 환경이 모두 달라 같은 자 위에 놓인 수치가 아니다.
6. **rp5 실기기에서는 측정하지 않았다.** 이 문서의 모든 숫자는 학습 PC 추론이다.
7. `fall` 세션의 비낙상 구간 오탐률 46.4%는 라벨 경계 효과와 실제 오탐이 섞여 있어
   **해석이 확정되지 않았다.**

## 6. 사람이 결정할 것

### ① 하드 네거티브를 언제, 어떻게 학습에 넣을 것인가
현재 96~99% 오탐은 배포 불가 수준이다. 선택지:
- **(a) 10월 계획대로** 하드 네거티브를 정식 수집해 학습에 포함 — 원래 계획
- **(b) 지금 있는 45건을 train/val로 쪼개 즉시 재학습** — 데이터가 적어 과적합 위험,
  대신 오탐이 실제로 잡히는지 빠르게 확인 가능
- 어느 쪽이든 **오늘 측정한 이 숫자가 "before" 기준선**이 된다.

### ② 임계값을 조정할 것인가
**이번에는 조정하지 않았다.** 0.5/0.7 둘 다 그대로 재고 나쁜 숫자를 그대로 적었다.
하드 네거티브 중앙값이 0.950이라 임계값을 올려도 오탐이 잡히지 않는다
(0.7 → 96.0%, 0.5 → 98.5%로 사실상 차이가 없다). **임계값으로는 풀리지 않는 문제다.**

### ③ `fall_longlie` 재현율 22.9%를 어떻게 볼 것인가
오래 누워 있는 낙상은 창 단위로 보면 "누운 정지 상태"라 낙상 순간의 급변이 창 밖으로
벗어난다. 라벨 정의(±1000ms)나 창 길이(1초)를 다시 볼 필요가 있는지 판단이 필요하다.
**이번에는 아무것도 바꾸지 않았다.**

### ④ 파일 간 편차의 원인 규명
`1327_fall` 86.0% vs `1340_fall` 37.5%, `1336_liedown` 5.6% vs `1337_liedown` 51.3%.
같은 행동인데 세션마다 크게 다르다. 노드 커버리지·피험자 위치·수집 시각 중
무엇이 원인인지 확인하지 않았다.
